# viewer 구조 정리 (2026-10-16)

오래 패치를 겹쳐 온 `viewer.py`를 동작을 바꾸지 않고 정리한 기록이다. 테스트 314개는 매 단계 통과했고, 실제 창을 띄워 세 가지 실험 종류의 모든 단계를 걸어 보는 smoke 실행으로도 확인했다.

## 진단

- 층 분리(domain / application / infrastructure / ui)는 지켜지고 있었다. domain에 Qt 없고, ui에 SQL 없다.
- 문제는 거의 전부 `viewer.py` 한 곳에 몰려 있었다(전체 104개 커밋 중 63개가 이 파일을 건드림).
- `ViewerWindow`는 사실상 두 개의 창이었다. 이미지 검토(약 1,500줄)와 실험 설계·저장(약 1,550줄)이고, 둘 사이 접점은 좁았다.
- `_create_editor`가 editor 객체에 바깥에서 속성 21개를 꽂아 넣었고, 클래스에 선언된 것은 2개뿐이라 `getattr(editor, …, None)` 방어 코드가 7군데 있었다.

## 한 일

1. **editor가 자기 실험 종류를 책임진다** (`aa710ce`)
   `PlanEditorBase`가 실험의 상태(어느 workspace, 어느 단계, 마지막 확정본 등)를 선언한다. 종류별 분기는 editor의 메서드가 되었다: `plan_snapshot()`, `draft(now)`, `record_builder()`, `has_plan_specific_content()`, `remember_opened_state()`. 확정본과 draft 행의 필드 순서는 그대로다(SQLite 왕복 테스트가 고정).
2. **죽은 코드 삭제와 복수형 통일** (`b180365`)
   호출자가 없던 `_selected_plate_format`(이미 없는 위젯을 참조해 호출하면 오류), `_instrument_label`, `page_for`, `rename_active_project`, `_toggle_cell`, `order_crystals`, `MxLiveReader` 등을 지웠다. 네 벌이던 복수형 함수는 `xtalflow/text.py`의 `counted()` 하나로 모았다.
3. **반복되는 새로고침에 이름 붙이기** (`fb64c8a`)
   `_adopt_active_review()` + `_sync_project_widgets()` 쌍 19곳 → `_show_active_review()`. workspace를 열고 보여 주는 try/except 3벌 → `_open_project_and_show()`.
4. **상태 판단을 editor로** (`7444e7a`)
   `ExperimentFacts`를 두 벌로 만들던 `_experiment_facts`가 `editor.facts(...)` 하나가 되었다. 실험 종류가 아는 것(남는 fragment, 필요한 well 수 등)은 그 editor가 더한다.
5. **창 분할** (`872f4c6`)
   실험 쪽 절반이 `ui/experiment_coordinator.py`로 나갔다. `window.experiments`로 닿는다. 두 쪽이 나눠 쓰는 것(project controller, 화면에 떠 있는 검토, 상태 표시줄, target dock)은 coordinator가 `self.window`로 가져간다. 이미지 읽기 실패 종류는 어느 쪽 것도 아니라 `ui/errors.py`로 옮겼다. 옮긴 코드에서 바뀐 것은 대화상자의 부모가 coordinator(위젯이 아님) 대신 창이 된 것뿐이다.
   - `viewer.py` 3,846줄 → 2,199줄, `ui/experiment_coordinator.py` 1,648줄.
6. **테스트만 쓰던 저장소 삭제** (`a441150`)
   `SQLiteFragmentLibraryStore`(fragment library를 DB에 넣던 것; 실제로는 CSV에서 읽는다)와 `SQLiteWorkspaceStore`의 image-set 이전 테이블용 메서드들을 지웠다. 리뷰 저장은 `SQLiteImageSetReviewStore`(실험 하나 × image set 하나)를 거친다. 테스트는 그 scoped 저장소를 쓰도록 바꾸었고, 마이그레이션 테스트 2개만 legacy `review_plan` 행을 SQL로 직접 읽는다. 스키마의 옛 테이블은 그대로 둔다(마이그레이션은 이력이라 고쳐 쓰지 않는다).
7. **예외 묶음 이름 붙이기** (`8b17c4a`)
   열두 번 적혀 있던 `(ValueError, ReviewPersistenceError)`가 `STORE_ERRORS`가 되었다. `IMAGE_SOURCE_ERRORS`는 여기에 공유가 끊길 때의 `OSError`를 더한 것이다.

- `ui/condition_test_editor.py`(2,176줄): Conditions 단계가 작은 표 편집기라 큰 것이고, 자족적이며 직접 테스트가 27개다. 크다는 이유만으로 쪼개지 않는다.
- `infrastructure/review_migrations.py`(835줄): 이력이므로 그대로 둔다.
- editor 생성자에 남은 `transient_project_id` 인자: 테스트가 창 없이 editor를 만들 때만 쓰인다. 정리 가치가 낮아 손대지 않았다.
- `viewer`가 `review_store.planning/workspace/audit`에 직접 닿는 10곳: 저장소들이 이미 repository 모양이라 한 겹 더 씌워도 결정이 줄지 않는다.

## 덧붙임: 이미지 공유가 끊겼을 때 (2026-10-16)

공유가 빠진 mountpoint는 평범한 빈 폴더로 보여서, 그동안 "공유가 끊김"과 "그런 plate 없음"이 같은 문구로 나왔다. 이제 둘을 구분한다.

- **판정 위치:** `RockMakerImageRepository` 안, **실패한 경로에서만**. 폴더가 없다고 판명된 그 자리에서 루트를 확인한다. 평소 읽기에는 비용이 없다. 새 예외 `ImageSourceUnavailable(OSError)`는 루트와 이유를 들고 다니고, `OSError`를 물려받아 기존 처리 지점은 그대로 동작한다.
- **운영/연습 구분:** `require_network_image_root`. 저장소 **밖**의 이미지 루트는 마운트된 공유여야 한다고 보고, 안쪽(연습용 fixture)이면 검사하지 않는다. 장비 폴더와 같은 방식이며, 예외가 필요하면 `--allow-local-image-root`.
- **재시도:** 창이 멈추지 않도록 공유 읽기를 백그라운드로 옮기고(`_read_images`), 실패하면 `Retry / Cancel`을 묻는다. 다시 시도는 **실제로 다시 읽는 것**이다. 죽은 CIFS 마운트도 마운트 표에는 남아 있어 표만 봐서는 돌아왔는지 알 수 없다. 두 번째 실패부터는 관리자에게 보여 줄 줄을 덧붙인다 — **컴퓨터 이름 · 경로 · OS 원문 오류**. 마운트는 컴퓨터마다 다르다.
- **없는 plate:** 재시도를 권하지 않는다(다시 봐도 없다). 입력 칸 아래 `No plate 9999 on the RockMaker share · check the number`, 대화상자 경로에서는 "RockMaker가 촬영하면 나타난다"는 한 줄을 더한다.
- **타이핑 중에는 창을 띄우지 않는다.** 수동 batch 선택 시 글자마다 공유를 읽던 자리는 조용한 오류 줄만 쓰고, 공유가 끊긴 게 확인되면 나머지 plate는 더 묻지 않고 멈춘다.
- **읽기 횟수:** plate 하나를 불러올 때 공유를 세 번 읽던 것을 한 번으로 줄였다. 읽은 이미지를 `add_pinned_image_set(..., plate)`로 넘긴다.
- **실험 화면:** 공유가 끊겨 선택한 well을 셀 수 없으면, 이제 Select wells 단계가 주의 상태로 **이유를 말하고** 확정을 막는다. 전에는 선택이 0개로 보이고 상태 표시줄에 한 줄 스쳐 갈 뿐이었다. `ExperimentFacts.images_unavailable`로 전달한다.
